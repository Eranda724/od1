### Answers for the Privacy Policy (alexghio)

---

**Q1. Will the app support Apple Sign-In, or only Google Sign-In?**

✅ **Both.** As of the latest build:
- **Google Sign-In** — Android + iOS
- **Apple Sign-In** — iOS only (Apple's own guideline allows this; no Android Apple Sign-In)
- **Email/password** — still supported on both platforms

---

**Q2. Besides email, exercise reps, history and streaks, what other user data is stored?**

From the Firestore schema confirmed across all services:

| Data | Where |
|---|---|
| Username / display name | `users/{uid}.displayName` |
| Email | `users/{uid}.email` |
| Exercise history & reps | `users/{uid}/exercises/*` |
| Overall + per-exercise streaks | `users/{uid}.overallStreak`, `exercises.currentStreak` |
| Leaderboard scores (daily/weekly/monthly) | `users/{uid}.scores` |
| Freeze tokens | `users/{uid}.freezesAvailable` |
| Friend pairs & shared streak | `friendPairs/{pairId}` |
| Friend requests (accepted/pending/rejected) | `friendRequests/{docId}` |
| Premium status (`isPremium`) | `users/{uid}.isPremium` |
| FCM push token (if using `firebase_messaging`) | `users/{uid}` (if stored — check `notification_service.dart`) |
| Profile photo (if uploaded) | Firebase Storage |

---

**Q3. Firebase Analytics, or only Google AdMob?**

✅ **AdMob only.** There is **no `firebase_analytics` package** in `pubspec.yaml`. No analytics SDK is integrated. Google AdMob (`google_mobile_ads`) is the only advertising/tracking service. Note: AdMob itself may collect device identifiers for ad targeting — this should be mentioned.

---

**Q4. Does the app send any emails?**

✅ **Yes — password reset only.** Firebase Auth sends a password reset email via the "Forgot Password" screen (`forgot_password_screen.dart`). No verification emails, no custom notification emails. Notifications are **local only** (scheduled on-device via `flutter_local_notifications`) — no server-sent push emails.

---

**Q5. Can users delete their account? Is personal data deleted?**

✅ **Yes — fully implemented.** The "Delete Account" button in Profile screen deletes:
- `users/{uid}/exercises/*` (sub-collection)
- `friendRequests` where user is sender or recipient
- `friendPairs` where user is a member
- `users/{uid}` document
- Firebase Auth record

All personal data is deleted from both Firestore and Firebase Auth.

---

**Q6. Anything else related to privacy / data collection?**

Worth mentioning:
- **`firebase_messaging`** is in the package list — if FCM tokens are stored in Firestore, that should be noted (device identifier)
- **`image_picker` + `firebase_storage`** — if users can upload profile photos, those are stored in Firebase Storage and should be deleted on account deletion (check if this is active)
- **`share_plus`** — app can share content to other apps; no data is sent to our servers via this
- **`in_app_purchase`** — purchase receipts are validated via the App Store/Play Store; no payment data is stored by the app
- **`google_mobile_ads`** — AdMob collects device advertising ID (IDFA on iOS, GAID on Android) for ad serving; this must be disclosed and covered by the ATT prompt on iOS 14+
